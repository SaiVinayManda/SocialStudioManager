# Versioned workflow exports

Twelve **inactive** export graphs, generated by `node scripts/generate-studio-workflows.mjs`. No workflow is imported/executed in this checkpoint. Import/publish requires the isolated deployment/local-auth grants. Stable workflow IDs `socialstudio0001` through `socialstudio0012`; HTTP credential reference `socialstudioauth` contains no key in the exports. API URLs are fixed internal service addresses; native tools execute only in the constrained Windows worker.

| ID suffix | Responsibility |
| --- | --- |
| 0001 | Signed intake, durable registration/deduplication, webhook acknowledgement and routing |
| 0002 | Typed deterministic AI metadata/fallback and persistence |
| 0003 | Queue existing-file validation or separately approved engine compose, persistent Wait/poll |
| 0004 | Enforce actual worker output validation |
| 0005 | Create checksum/version-bound review, preview/local notification, Wait for explicit decision; expiry/rejection never approve |
| 0006 | Schedule/atomically claim due work, require fresh native file verification, route platform |
| 0007–0009 | Separate YouTube/Instagram/Facebook mock dispatch |
| 0010 | Persist local operator notifications |
| 0011 | Error/recovery tick, bounded durable recovery operations |
| 0012 | Signed reporting webhook using durable state |

No Code, Execute Command, SSH, local file trigger, arbitrary workflow ID/URL or plaintext static secret node. Successful execution data is retained for acceptance; error payload storage disabled. Runtime compatibility with pinned n8n is still unverified. The official 2.45.7 Execute Workflow source supports passthrough triggers without a workflowInputs mapper and async child execution; actual imports/expressions/Wait recovery must still be tested. The genuine acceptance script checks all 12 execution IDs in the new PostgreSQL n8n database rather than simulating graphs in application code.
